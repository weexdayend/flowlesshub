## Acceptance boundary

Scheduled production execution is fail-closed for off-site delivery. The systemd service explicitly sets `FLOWLESSHUB_OFFSITE_REQUIRED=1`; the orchestrator rejects a missing flag before creating a backup. An off-site disabled/not-configured result (exit 3) or upload/read-back error must make the service fail, skip retention, and trigger the Discord `OnFailure` hook. Local backup-only completion is not accepted as scheduled production success. The unit tests cover these orchestration branches; they do not replace the real R2 one-shot acceptance.

- A systemd timer parsing successfully is not proof that a scheduled backup ran.
- A Restic snapshot listing is not proof that archive data can be read. The uploader now reads back the archive triplet and compares hashes before writing a marker; this targeted check is still not a PostgreSQL restore drill or full remote-repository integrity audit.
- A local marker is not sufficient by itself; retention validates all three recorded hashes and the live snapshot, then `--apply` freshly reads back the archive triplet and compares hashes immediately before local deletion.
- This package does not prune remote snapshots or automatically restore production data.
- A one-second S0.10 PostgreSQL restore duration is not service RTO; RPO/RTO values require explicit owner targets and operational evidence.
- Backup/off-site/retention and Discord test-delivery runtime checks are verified by the 13 November 2026 evidence above. S0.11 remains open and is not owner accepted until the remaining production-success evidence is considered and the owner explicitly accepts the checkpoint. Timer activation, local deletion, and remote pruning remain separately gated and are not part of this acceptance.
