# S0.8 — Edge validation repair

**Base:** `f949f896514cb871d1cbaeb2c01aac3195d6e546`
**Purpose:** Repair the S0.8 CI failure in `make edge-validate`.

The original Makefile target referenced `scripts/k8s/validate-edge-config.sh` and `scripts/k8s/validate-edge-manifests.sh`, but those files were not present in the pushed S0.8 commit. GitHub Actions therefore failed with exit code 127 before running Caddy validation.

This repair replaces the missing Bash scripts with `scripts/k8s/validate-edge.mjs`, adds Node.js 22.16.0 to the backend CI job, and makes `make edge-validate` invoke the new script. The script validates blue/green Deployment/Pod/Service identity, verifies the base edge Service is ClusterIP, verifies the generated Caddy ConfigMap inputs, pulls pinned `caddy:2.11.9-alpine`, validates the local Caddyfile, and adapts the production Caddyfile.

The Caddy edge readiness probe is also changed from `curl` to BusyBox `wget`, which is available in the pinned Alpine-based Caddy image and avoids depending on curl being installed.

This record does not claim acceptance. Exact-HEAD CI and local Caddy/Docker validation must pass after the repair commit is pushed.
