# S0.4 — PostgreSQL Migration Lint and sqlc Code Generation

**Status:** Patch prepared against `c281d0ce4ffae945ae4f4aa6ec9450237f26c94b`; local owner validation and remote CI acceptance are pending. S0 remains open.

## Goal

Make the PostgreSQL migration and query-code generation path reproducible and enforceable in CI. This slice closes the tooling gap between the existing Goose migration directory and the existing sqlc configuration; it does not claim database runtime or production migration readiness.

## Scope

- Pin Squawk CLI `v2.72.0` for migration linting. The Linux x64 CI binary is downloaded from the official release and verified against its published SHA-256 before execution.
- Lint Goose SQL files with PostgreSQL 17 semantics, explicitly enable the opt-in `require-timeout-settings` rule, and use `--assume-in-transaction` to match Goose's transactional Up/Down migration execution.
- Keep the existing `SET LOCAL lock_timeout` and `SET LOCAL statement_timeout` in each migration direction.
- Add one narrowly scoped `squawk-ignore ban-drop-schema` comment to the foundation migration's Down statement. Dropping this empty bootstrap schema is the intended rollback; no rule is disabled globally.
- Pin sqlc `v1.31.1` in the existing Makefile target and CI, generate the pgx/v5 package into `internal/platform/dbgen`, and commit all generated outputs.
- Make CI fail when generated sqlc outputs are missing, modified by regeneration, or unexpectedly untracked.

## Generated package

`services/api/internal/platform/dbgen` contains `db.go`, `models.go`, `querier.go`, and `platform.sql.go`. It is generated from `sqlc.yaml` and `db/queries/platform.sql`; do not hand-edit these files. Regenerate using `make sqlc` from the repository root.

The current `Ping` query is a deliberately small foundation query. It proves that the sqlc pipeline emits a pgx/v5 query method returning `int64`; it is not yet a business-domain repository API.

## Validation

1. Squawk reports no issues for committed Goose migration files with the opt-in `require-timeout-settings` rule explicitly enabled.
2. A temporary unsafe `ALTER TABLE ... ADD COLUMN` migration fails lint with both lock-timeout and statement-timeout diagnostics; the probe is removed afterward.
3. `sqlc generate` reproduces the four committed generated files with no Git diff and no untracked generator output.
4. Backend architecture lint, gofmt, `go mod tidy -diff`, `go mod verify`, vet, and tests pass.
5. Frontend install, generated OpenAPI sync, lint, typecheck, and build remain green.
6. CI passes on the owner-pushed commit.
