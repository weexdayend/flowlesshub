## Goal and scope

Harden the existing FlowlessHub logical PostgreSQL backup, verify the archive and its metadata, produce an independently checked workstation copy, and prove a full restore into a disposable isolated PostgreSQL container. A production database restore is explicitly prohibited by this checkpoint.

## Implementation decisions

- Use PostgreSQL custom-format `pg_dump` with `--no-owner --no-privileges`.
- Keep backups under `.vps-runtime/backups/`, ignored by Git.
- Write archive, SHA-256 sidecar, and non-secret manifest with mode `0600`; backup directory uses mode `0700`.
- Protect `.vps-runtime/.env` with mode `0600` and verify it is Git-ignored before any database access.
- Serialize backup and restore operations through `.vps-runtime/backup.lock` using `flock -n`.
- Enforce RAM, swap, and disk guards; do not lower them to force an operation.
- Verify the archive catalog via a network-isolated, read-only, resource-limited PostgreSQL helper container using the local pinned image `postgres:17.11-alpine`. Do not implicitly pull the image.
- Include UTC time, source commit, active color, DB name/version/size, schema/relation counts, archive filename and checksum in the manifest; never include credentials.
- Validate sidecar permissions, filename, manifest consistency, SHA-256, PostgreSQL major version, and `pg_restore --list` readability.
- Restore only into `flowlesshub_restore` in a disposable container with `--network none`, no published ports, 256 MiB memory, swap disabled, 0.50 CPU, anonymous ephemeral data volume, and `--rm`.
- Use `pg_restore --exit-on-error --single-transaction --no-owner --no-privileges`; compare restored schema/relation counts with manifest and verify `platform` exists.
- Recheck production PostgreSQL health and active-color state after the drill.
- Keep Bash scripts LF through `.gitattributes`; CI verifies `100755`, `bash -n`, and ShellCheck for every tracked `scripts/vps/*.sh`.

## Explicit non-goals and follow-ups

S0.10 did not deliver automated scheduling, local retention policy, geographic/cloud off-site storage, recurring restore cadence, external failure alerting, or agreed RPO/RTO objectives. The Windows workstation copy is not a geographic disaster-recovery copy. One-second PostgreSQL restore duration is not whole-service RTO. These topics belong to S0.11 and later owner-approved operations work.
