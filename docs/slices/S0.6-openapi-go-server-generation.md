# S0.6 — OpenAPI Go Strict Server Generation

**Status:** Implementation prepared; owner generation/validation and exact-HEAD CI acceptance are pending. S0 remains open.

## Goal

Complete the Go side of the foundation OpenAPI-first pipeline. Generate and commit Go models plus Chi server and strict-server interfaces from the existing OpenAPI 3.1 contract, and make backend CI fail when generated code is missing or stale.

## Current contract

- Source of truth: `api/openapi.yaml`.
- Current operations: `GET /livez` (`getLiveness`) and `GET /readyz` (`getReadiness`).
- Existing TypeScript client: `packages/api-client/src/generated/openapi.d.ts`, generated by `pnpm api:generate` and already freshness-checked by frontend CI.
- Existing Go generator config: `services/api/oapi-codegen.yaml`.
- Generated Go destination: `services/api/internal/platform/httpapi/openapi.gen.go` (package `platformapi`).

## Decisions

- Pin `oapi-codegen` at v2.8.1 through the existing versioned `go run ...@v2.8.1` invocation. This release line supports OpenAPI 3.1; v2.8.1 includes subsequent security fixes.
- Generate models, Chi server routing/interface and strict-server interface in the same package.
- Keep generated output committed. Never hand-edit `openapi.gen.go`; change `api/openapi.yaml` or `oapi-codegen.yaml`, regenerate, and review the diff.
- Ensure the output directory exists before generation. The Make target creates it, so a fresh checkout can run the target without a pre-created directory.
- Backend CI regenerates the Go server and checks that the generated file is tracked, byte-for-byte current, and not accompanied by untracked output.
- The normal `go test ./...` step compiles generated stubs as part of backend validation.

## Runtime compatibility

This slice adds a generated contract artifact and enforcement only. Existing `/livez` and `/readyz` handlers and route registration remain unchanged. The generated `ServerInterface`, `StrictServerInterface`, and Chi handler factory become the contract-driven foundation for subsequent API vertical slices; this patch does not silently change runtime behavior.

## Scope

- Enable `strict-server: true` alongside the current `chi-server: true` and model generation.
- Make `openapi-go` create `internal/platform/httpapi` before invoking the pinned generator.
- Add backend CI generation and freshness checks for `openapi.gen.go`.
- Add this slice specification and owner runbook.
- Generate and commit `services/api/internal/platform/httpapi/openapi.gen.go` using the exact pinned command in the runbook. The generated artifact is intentionally produced by the generator on the owner toolchain, not hand-authored in this patch.

## Invariants

- `api/openapi.yaml` and the TypeScript generated client are unchanged.
- No endpoint, request/response schema, operation ID, status code or runtime route behavior changes.
- No business module, database schema, migration, permission, tenant table, RLS policy or event is introduced.
- No dependency is added to `go.mod` unless the generated output actually requires it; the current health-only contract has no request body or parameters.
- `CHECKPOINTS.md` is not edited or checked by this implementation-only slice. The S0 item remains open pending the complete S0 Definition of Done and exit gate.

## Acceptance

1. The pinned generator succeeds from a fresh checkout and emits `openapi.gen.go` with package `platformapi`.
2. The generated output contains the models, Chi `ServerInterface`/`HandlerFromMux`, and `StrictServerInterface`/strict handler adapter for the declared operations.
3. Re-running generation produces no diff.
4. `go test ./...`, `go vet ./...`, module tidy/verification, formatting, and frontend quality gates pass.
5. Backend CI verifies the generated artifact is tracked/current and exact-HEAD frontend and backend jobs pass.
6. No runtime health-probe behavior or API contract changes.

## Non-goals

- No strict handler implementation or route migration in the live API composition root yet.
- No request-validation middleware, security schemes, authentication, authorization, client/vendor DTOs or business endpoints.
- No OpenAPI breaking-change diff policy expansion in this slice; this slice closes generated Go stubs/freshness only.
- No claim that S0 is complete or production-deployable.
