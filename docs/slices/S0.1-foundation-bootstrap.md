# S0.1 — Repository Foundation Bootstrap

**Status:** In progress; implementation scaffold only. The S0 exit gate is not satisfied.

## Context

The repository begins with a standalone Next.js create-next-app scaffold and a backend directory containing only a Go module declaration. The approved Technical Architecture calls for a pnpm/Turborepo workspace, a Next.js web application, shared packages, and a Go modular monolith with separate API and worker entry points.

## Scope

- Establish the intended monorepo paths without implementing business modules.
- Move the existing Next.js application to `apps/web` and preserve its Next.js agent instructions.
- Add shared `packages/ui`, `packages/api-client` and `packages/config` foundations.
- Establish the OpenAPI 3.1 source contract for liveness/readiness only.
- Bootstrap Go API and worker entry points, PostgreSQL connectivity, River worker client and a versioned cryptokit header type.
- Add independent backend and frontend Compose files and an initial CI quality-gate workflow.
- Add the root agent working agreement and this slice specification.

## Explicit non-goals

- No tenant, user, client, project, RAB, contract, finance or other business tables.
- No authentication, RBAC, RLS policies or audit chain yet; these belong to S1 and must be designed as a vertical slice before implementation.
- No actual encryption primitive or ML-KEM/ML-DSA operation; this slice only defines the versioned envelope header contract.
- No production deployment, traffic switching, backup restore drill or zero-downtime migration claim.

## Decisions

- Retain the modular-monolith direction and separate API/worker processes.
- Use PostgreSQL as the source of truth; this slice only wires connectivity and a minimal platform schema namespace.
- Keep backend and frontend Compose projects independent.
- Use `/livez` for process liveness and `/readyz` for PostgreSQL readiness.
- Keep all checkpoint boxes untouched until evidence satisfies the documented Global Definition of Done and exit gate.
