# S0.3 — Go Module-Boundary Lint

**Status:** Implementation prepared; owner validation and green CI are pending. S0 remains open.

## Context

The S0 backend currently contains cross-cutting packages under `internal/kernel`, infrastructure adapters under `internal/platform`, three process entrypoints (`cmd/api`, `cmd/worker`, and `cmd/migrate`), and the embedded SQL migration package (`db/migrations`). The architecture document requires strict modular-monolith boundaries and names `depguard` or `go-arch-lint` as the enforcement mechanism.

## Decision

Use `go-arch-lint` v1.16.0 with a checked-in v3 architecture file at `services/api/.go-arch-lint.yml`. The rule set maps every current Go package to an explicit component and fails when a future package is not mapped.

Allowed internal dependency edges for the current repository:

| Source component | May import internal components |
| --- | --- |
| `kernel` | None |
| `platform` | `kernel` |
| `migrations` | None |
| `api` composition root | `kernel`, `platform` |
| `worker` composition root | `kernel`, `platform` |
| `migrate` composition root | `kernel`, `platform`, `migrations` |

Third-party Go dependencies are allowed in the components. The rule concerns project-internal package dependencies; it does not impose a dependency allowlist on standard-library or pinned external imports.

## Guardrails for future modules

- A new Go package that is not covered by a declared component is a lint failure (`ignoreNotFoundComponents: false`).
- When a business module is introduced under `internal/<module>`, add a component for that module and explicitly list only its permitted dependencies before adding imports.
- Do not group all future business modules into one wildcard component: that would hide forbidden sibling-module imports inside the same component.
- Feature modules may depend on shared kernel contracts only as explicitly declared; they must not import sibling modules to read or mutate their tables.
- Keep entrypoints as composition roots. Do not allow application internals to depend on `cmd/*` packages.

## Enforcement

- `make arch-lint` runs the pinned linter locally.
- Backend CI runs the same pinned command before Go formatting, vet and test gates.
- The runbook includes a temporary negative probe that attempts `kernel -> platform`; the linter must reject it, and the probe is removed before normal tests or commit.

## Non-goals

- No business-domain module, database table, migration, endpoint, permission, event or UI is introduced by this slice.
- No checkpoint is marked complete by this patch; CI enforcement and owner validation are still required.
- No `depguard` policy is introduced in parallel; one architecture linter is sufficient for this checkpoint item.
