## 2. Positive architecture check

The architecture file is scoped to the `services/api` Go module. The command is pinned to `go-arch-lint v1.16.0`; it does not change `go.mod` or `go.sum`.

```powershell
go -C .\services\api run github.com/fe3dback/go-arch-lint@v1.16.0 check --project-path .
if ($LASTEXITCODE -ne 0) { throw "Go architecture boundary check failed" }
```

Expected: exit code `0` and no unclassified package or dependency violation.

The exact dependency policy is:

The closed `kernel` and `migrations` rules use a self-reference because go-arch-lint v1.16.0 rejects an empty `mayDependOn` list and does not treat `anyProjectDeps: false` as a qualifying rule. The self-reference permits only same-component packages; it does not allow imports from other components.

- `kernel` may depend only on packages classified in the `kernel` component (self-reference; no other project component).
- `platform` may import `kernel`.
- `migrations` may depend only on packages classified in the `migrations` component (self-reference; no other project component).
- `api` and `worker` may import `kernel` and `platform`.
- `migrate` may import `kernel`, `platform` and `migrations`.
- All third-party imports remain allowed.

## 3. Negative policy probe (must be rejected)

This temporary source file deliberately adds the forbidden edge `kernel -> platform`. It must never be committed.

```powershell
$probePath = Join-Path (Get-Location).Path "services\api\internal\kernel\config\architecture_probe.go"
if (Test-Path $probePath) { throw "Architecture probe already exists; inspect it before continuing" }

$probeSource = @'
package config

import "github.com/weexdayend/flowlesshub/services/api/internal/platform/database"

var _ = database.Open
'@
$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($probePath, $probeSource, $utf8NoBom)

try {
    $probeOutput = & go -C .\services\api run github.com/fe3dback/go-arch-lint@v1.16.0 check --project-path . 2>&1
    $probeExitCode = $LASTEXITCODE
    $probeOutput | ForEach-Object { Write-Host $_ }
    if ($probeExitCode -eq 0) {
        throw "Architecture linter accepted the deliberate kernel -> platform violation"
    }
} finally {
    if (Test-Path $probePath) { Remove-Item -Force $probePath }
}

if (Test-Path $probePath) { throw "Temporary architecture probe was not removed" }
```

Expected: the linter exits non-zero while the probe exists and reports a component dependency violation. The `finally` block removes the probe even if the command fails. Do not proceed if the diagnostic shows a configuration/tool-loading error instead of the intended boundary violation; investigate it first.

Re-run the normal positive check after probe removal:

