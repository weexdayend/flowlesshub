# FLOWLESSHUB — S0.2 Runtime Harness HEAD Guard Correction

**Patch baseline:** `32dc13661fa21d6822aa243d48e1d17775917065`
**Audited runtime baseline retained by the script:** `c2cc54065cf49410538f4abed850567741dee813`
**Target:** Windows PowerShell 5.1+ or PowerShell 7+, Git, Node.js >=22.13.1, pnpm 12.18.0, Go 1.27.4, Docker Desktop with Compose v2.

This follow-up fixes a real defect in the committed S0.2 runtime harness. The previous script required HEAD to equal `c2cc540...`, even though the harness itself was committed later at `32dc136...`. The corrected script now accepts any descendant of the audited baseline only when the runtime-sensitive files have not changed. Documentation/script edits do not block execution; uncommitted runtime inputs still do.

### 6.1 Squawk positive and negative policy checks

Install the pinned Squawk v2.72.0 Windows binary and verify its SHA-256 before running it:

```powershell
$toolDir = Join-Path $env:LOCALAPPDATA "FlowlessHub\tools"
New-Item -ItemType Directory -Force -Path $toolDir | Out-Null
$Squawk = Join-Path $toolDir "squawk-windows-x64.exe"
$url = "https://github.com/sbdchd/squawk/releases/download/v2.72.0/squawk-windows-x64.exe"
$expectedSha256 = "dd36bf596181802b8b44512417e5ae5c133ae6be126d7563117f476ccdd9900a"

if (-not (Test-Path -LiteralPath $Squawk -PathType Leaf)) {
    $download = Join-Path $toolDir "squawk-windows-x64.download"
    $ProgressPreference = "SilentlyContinue"
    Invoke-WebRequest -Uri $url -OutFile $download -ErrorAction Stop
    $actualSha256 = (Get-FileHash -Path $download -Algorithm SHA256).Hash.ToLowerInvariant()
    if ($actualSha256 -ne $expectedSha256) {
        Remove-Item -Force $download
        throw "Squawk SHA-256 mismatch: $actualSha256"
    }
    Move-Item -Force $download $Squawk
}

$actualSha256 = (Get-FileHash -Path $Squawk -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actualSha256 -ne $expectedSha256) { throw "Squawk SHA-256 mismatch: $actualSha256" }

& $Squawk --version
if ($LASTEXITCODE -ne 0) { throw "Squawk failed to start" }
```

Then run the positive and negative policy tests:

```powershell
& $Squawk --pg-version=17.0 --assume-in-transaction --include=require-timeout-settings "services/api/db/migrations/*.sql"
if ($LASTEXITCODE -ne 0) { throw "Squawk reported committed migration issues" }

$probe = Join-Path (Resolve-Path ".\services\api\db\migrations") "99999_squawk_negative_probe.sql"
if (Test-Path -LiteralPath $probe) { throw "Probe path already exists: $probe" }
try {
    $probeSql = @'
-- +goose Up
ALTER TABLE public.squawk_probe ADD COLUMN unsafe_text text;
'@
    [System.IO.File]::WriteAllText($probe, $probeSql, [System.Text.UTF8Encoding]::new($false))
    $probeOutput = (& $Squawk --pg-version=17.0 --assume-in-transaction --include=require-timeout-settings $probe 2>&1 | Out-String)
    $probeExit = $LASTEXITCODE
    if ($probeExit -eq 0) { throw "Squawk unexpectedly accepted the unsafe migration probe" }
    if ($probeOutput -notmatch "require-lock-timeout") { throw "Missing require-lock-timeout diagnostic`n$probeOutput" }
    if ($probeOutput -notmatch "require-statement-timeout") { throw "Missing require-statement-timeout diagnostic`n$probeOutput" }
}
finally {
    if (Test-Path -LiteralPath $probe) { Remove-Item -Force $probe }
}

& $Squawk --pg-version=17.0 --assume-in-transaction --include=require-timeout-settings "services/api/db/migrations/*.sql"
if ($LASTEXITCODE -ne 0) { throw "Squawk lint failed after negative-probe cleanup" }
```

## 7. Run S0.2 disposable runtime acceptance

The corrected script is designed to run from the current committed HEAD or from a working tree with documentation/harness edits. It validates that HEAD descends from `c2cc540...` and that runtime-sensitive paths remain identical to that baseline. It deliberately does not require the entire repository to be clean.

```powershell
.\scripts\validate-s0.2-runtime.ps1 -TimeoutSeconds 300
if ($LASTEXITCODE -ne 0) { throw "S0.2 runtime acceptance failed" }
```

The harness creates a unique project/volume, checks fresh-volume Goose and River migrations, start ordering, PgBouncer `SELECT 1`, API liveness/readiness including the PgBouncer outage negative test, API/worker database routing, worker stability, and migration idempotency. It cleans only its own project and volume. Use `-KeepResources` only when preserving the disposable stack for diagnostics:

```powershell
.\scripts\validate-s0.2-runtime.ps1 -TimeoutSeconds 300 -KeepResources
```

To remove preserved resources, use only the project name printed by the script:

```powershell
$projectName = Read-Host "Disposable project name printed by the harness"
docker compose --project-name $projectName --file .\deploy\compose\backend.compose.yaml down --volumes --remove-orphans
if ($LASTEXITCODE -ne 0) { throw "Disposable project cleanup failed" }
```

Never run `docker compose down -v` against the normal `flowlesshub-backend` project.
