# FlowlessHub S0.8 — Caddy Edge, Blue/Green Switch, and Rollback Runbook

**Patch:** `FLOWLESSHUB-S0.8-REVERSE-PROXY-BLUE-GREEN.patch`
**Exact baseline:** `bcd1ba94248ff4cfbcb06c9634eaccc6f9f6de2f`
**Target:** `main`
**Local runtime:** Windows PowerShell 5.1+ or PowerShell 7+, Docker Desktop Kubernetes (`docker-desktop`)
**Scope:** Caddy edge proxy, color-specific web/API Services, blue/green routing, API readiness drain, edge/web graceful termination, CI validation, and local switch/rollback rehearsal.

This patch does not change `CHECKPOINTS.md`, database migrations, worker lifecycle, OpenAPI, product scope, or the S0 exit gate. Production overlay is rendered/validated only; do not apply it without a real hostname, TLS Secret, and production LoadBalancer.

## 13. Failed-candidate protection rehearsal (recommended)

This deliberately removes the green API endpoints, tries to switch to green, and verifies that the old blue edge Pods continue serving because the edge Deployment has `maxUnavailable: 0`. The expected rollout timeout is a successful fault-injection result.

```powershell
kubectl scale deployment/flowlesshub-api-green --namespace flowlesshub --replicas=0
if ($LASTEXITCODE -ne 0) { throw "Unable to scale green API to zero for fault injection." }

kubectl set env deployment/flowlesshub-edge --namespace flowlesshub FLOWLESSHUB_ACTIVE_COLOR=green
if ($LASTEXITCODE -ne 0) { throw "Unable to attempt the green edge switch." }

kubectl rollout status deployment/flowlesshub-edge --namespace flowlesshub --timeout=25s
$expectedBlockedRolloutExit = $LASTEXITCODE

if ($expectedBlockedRolloutExit -eq 0) {
    throw "Green edge unexpectedly became Ready without green API endpoints."
}

$stillServingBlue = Invoke-WebRequest -UseBasicParsing -Uri "$baseUri/" -TimeoutSec 20
if ($stillServingBlue.StatusCode -ne 200) { throw "Existing blue edge stopped serving during failed switch." }

$stillServingColor = [string]$stillServingBlue.Headers["X-FlowlessHub-Active-Color"]
if ($stillServingColor -ne "blue") {
    throw "Expected old edge replicas to remain on blue during blocked rollout; found '$stillServingColor'."
}

# Roll back first, then restore the green API replica.
kubectl set env deployment/flowlesshub-edge --namespace flowlesshub FLOWLESSHUB_ACTIVE_COLOR=blue
if ($LASTEXITCODE -ne 0) { throw "Failed to restore blue active color." }

kubectl rollout status deployment/flowlesshub-edge --namespace flowlesshub --timeout=180s
if ($LASTEXITCODE -ne 0) { throw "Edge failed to recover to blue." }

kubectl scale deployment/flowlesshub-api-green --namespace flowlesshub --replicas=1
if ($LASTEXITCODE -ne 0) { throw "Unable to restore green API replica." }

kubectl rollout status deployment/flowlesshub-api-green --namespace flowlesshub --timeout=180s
if ($LASTEXITCODE -ne 0) { throw "Green API did not recover after fault injection." }

Write-Host "Unready-candidate traffic protection and recovery passed." -ForegroundColor Green
```

This fault injection only tests the API readiness gate. The normal successful switch in Section 11 separately checks green web and API readiness before activation.

## 15. Production TLS overlay preflight — render only

Do not apply the production or production-green overlays in local Docker Desktop. It requires a real FQDN, an externally managed certificate/key, and a cluster LoadBalancer implementation.

Before a real production apply, an operator must:
1. Replace `FLOWLESSHUB_SITE_ADDRESS` in `flowlesshub-edge-runtime` with the real public FQDN.
2. Provision Secret `flowlesshub-edge-tls` with `tls.crt` and `tls.key` via the production certificate/secret manager.
3. Verify DNS points at the LoadBalancer and ports 80/443 are reachable.
4. Apply `deploy/k8s/overlays/production` only after the certificate and hostname checks pass.
5. Verify HTTPS, certificate chain, TLS 1.3, and hybrid `X25519MLKEM768` negotiation at the edge. Do not override Caddy TLS curves/cipher defaults to force a test result.

No public domain or certificate is invented by this runbook.

}
