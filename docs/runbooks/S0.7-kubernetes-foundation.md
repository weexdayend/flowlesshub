# FlowlessHub S0.7 — Kubernetes Foundation and Container Image Runbook

**Patch baseline:** `54a53247c57aa6fbb0abf8c355fb24a41ea380fa`

**Target:** Windows PowerShell 5.1+ or PowerShell 7+, Git, Docker Desktop with Buildx, Go 1.27.4, Node.js >=22.13.1, pnpm 12.18.0. A Kubernetes cluster is optional for the local acceptance steps and is only used for the isolated deployment smoke test in Section 8.

This runbook starts by moving the downloaded patch to `%TEMP%`, before any clean-tree check. It applies the exact-baseline patch, renders Kustomize packages, builds all four container images, runs backend/frontend regression gates, verifies exact patch scope, and provides an optional migration-first Kubernetes smoke test. CI builds images but does not publish them.

## 1. Mandatory artifact relocation, exact baseline and clean preflight

Run from any directory inside the repository. **Do not run `git status` before this block.** A patch downloaded into the repository root is an untracked file and will make the clean-tree check fail; this block moves it out first.

```powershell
$ErrorActionPreference = "Stop"

# Resolve repository root and enter it.
$repoRoot = (git rev-parse --show-toplevel | Out-String).Trim()
if ($LASTEXITCODE -ne 0 -or [string]::IsNullOrWhiteSpace($repoRoot)) {
    throw "Unable to resolve Git repository root"
}
Set-Location $repoRoot

# Move the downloaded patch to TEMP before checking Git status.
$patchName = "FLOWLESSHUB-S0.7-KUBERNETES-FOUNDATION.patch"
$patchInRepo = Join-Path $repoRoot $patchName
$patchInTemp = Join-Path $env:TEMP $patchName
$hasRepoPatch = Test-Path -LiteralPath $patchInRepo -PathType Leaf
$hasTempPatch = Test-Path -LiteralPath $patchInTemp -PathType Leaf

if ($hasRepoPatch -and $hasTempPatch) {
    $repoHash = (Get-FileHash -LiteralPath $patchInRepo -Algorithm SHA256).Hash
    $tempHash = (Get-FileHash -LiteralPath $patchInTemp -Algorithm SHA256).Hash
    if ($repoHash -ne $tempHash) {
        throw "Different patch files exist in repository root and TEMP. Neither copy was deleted. Inspect both files."
    }
    Remove-Item -LiteralPath $patchInRepo -Force
}
elseif ($hasRepoPatch) {
    Move-Item -LiteralPath $patchInRepo -Destination $patchInTemp
}
elseif (-not $hasTempPatch) {
    throw "Patch not found. Place $patchName in repository root or %TEMP%."
}

$patch = $patchInTemp
if (-not (Test-Path -LiteralPath $patch -PathType Leaf)) {
    throw "Patch relocation failed: $patch"
}
Write-Host "Patch safely located outside repository: $patch" -ForegroundColor Green

# Verify the exact pushed baseline.
$expectedHead = "54a53247c57aa6fbb0abf8c355fb24a41ea380fa"
$actualHead = (git rev-parse HEAD).Trim()
if ($LASTEXITCODE -ne 0) { throw "Unable to read Git HEAD" }
if ($actualHead -ne $expectedHead) { throw "Unexpected HEAD: $actualHead" }

# Verify exact blobs of the existing files this patch changes.
$expectedBlobs = @{
    "Makefile" = "88455b8bba60838e1d59f0c8e19413a70d46bb10"
    ".github/workflows/ci.yml" = "81ee53eb4035f97bfbe3f9ac0a9d4f64e19ef3e2"
}
foreach ($path in $expectedBlobs.Keys) {
    $actualBlob = (git rev-parse "HEAD:$path").Trim()
    if ($LASTEXITCODE -ne 0) { throw "Unable to resolve blob for $path" }
    if ($actualBlob -ne $expectedBlobs[$path]) {
        throw "Unexpected baseline blob for ${path}: $actualBlob"
    }
}

# Clean-tree checks happen only after artifact relocation.
$status = @(git status --short --untracked-files=all)
if ($status.Count -gt 0) {
    throw "Repository must be clean before applying patch: $($status -join ', ')"
}
git diff --quiet
if ($LASTEXITCODE -ne 0) { throw "Tracked working-tree changes detected" }
git diff --cached --quiet
if ($LASTEXITCODE -ne 0) { throw "Staged changes detected" }
```

Never reset, clean, or delete unrelated repository files to satisfy this preflight. Keep the patch in `%TEMP%` for the entire run.

## 4. Render and validate both Kubernetes packages

Kustomize is pinned to v5.8.3, the repository's selected release for this slice. Both packages must render without contacting a cluster.

```powershell
$baseOutput = & go run sigs.k8s.io/kustomize/kustomize/v5@v5.8.3 build .\deploy\k8s\base
if ($LASTEXITCODE -ne 0) { throw "Kustomize base render failed" }
$baseYaml = $baseOutput -join "`n"

$migrationOutput = & go run sigs.k8s.io/kustomize/kustomize/v5@v5.8.3 build .\deploy\k8s\migrations
if ($LASTEXITCODE -ne 0) { throw "Kustomize migration render failed" }
$migrationYaml = $migrationOutput -join "`n"

foreach ($required in @(
    "kind: Namespace",
    "name: flowlesshub",
    "kind: ConfigMap",
    "kind: Deployment",
    "name: flowlesshub-api",
    "name: flowlesshub-web",
    "name: flowlesshub-worker",
    "kind: Service"
)) {
    if ($baseYaml -notmatch [regex]::Escape($required)) {
        throw "Rendered base is missing expected manifest marker: $required"
    }
}

$deploymentCount = [regex]::Matches($baseYaml, '(?m)^kind: Deployment$').Count
$serviceCount = [regex]::Matches($baseYaml, '(?m)^kind: Service$').Count
if ($deploymentCount -ne 3) { throw "Expected 3 Deployments; rendered $deploymentCount" }
if ($serviceCount -ne 2) { throw "Expected 2 Services; rendered $serviceCount" }

if ($migrationYaml -notmatch '(?m)^kind: Job$') { throw "Migration package does not render a Job" }
if ($migrationYaml -notmatch 'DATABASE_URL_MIGRATE') { throw "Migration Job is missing the dedicated migration database secret key" }
if ($migrationYaml -notmatch 'flowlesshub-runtime-secrets') { throw "Migration Job is missing its external Secret reference" }

if ($baseYaml -match '(?i)password\s*:|postgres://[^\s]+:[^@\s]+@') {
    throw "Rendered base unexpectedly contains inline credentials"
}
if ($migrationYaml -match '(?i)password\s*:|postgres://[^\s]+:[^@\s]+@') {
    throw "Rendered migration manifest unexpectedly contains inline credentials"
}

Write-Host "Kustomize base: 3 Deployments, 2 Services, namespace and ConfigMap validated." -ForegroundColor Green
Write-Host "Kustomize migrations: one-shot Job and external Secret reference validated." -ForegroundColor Green
```

## 8. Optional isolated Kubernetes smoke test

This section uses a disposable Docker Desktop Kubernetes cluster. The helper provisions a local-only PostgreSQL/PgBouncer pair *inside Kubernetes* so application Pods use cluster DNS and do not depend on Windows host routing, `host.docker.internal`, Windows Firewall rules, or published host ports. It does not use or modify the existing `postgres-db` container on host port `5432`.

Run the helper from the repository root:

```powershell
& .\scripts\k8s\provision-local-runtime.ps1
if ($LASTEXITCODE -ne 0) { throw "Local Kubernetes runtime provisioning failed" }
```

The helper performs these steps:

- Confirms the active context is `docker-desktop` and the Kubernetes API is reachable.
- Creates a dedicated random local database password in process memory and stores the database credentials in a Kubernetes Secret. Reruns reuse the existing Secret; the password is never printed or written to a file.
- Applies one local-only Deployment with PostgreSQL 17.11 and PgBouncer 1.26.1 as sidecars, plus a ClusterIP Service. Both containers run non-root under the namespace's Restricted Pod Security policy.
- Uses a bounded `emptyDir` volume (2 GiB) for PostgreSQL, with `PGDATA=/var/lib/postgresql/data/pgdata` nested below the volume mount. The child directory is created by UID/GID 70 inside the fsGroup-writable mount, allowing the official PostgreSQL entrypoint to set directory permissions without trying to `chmod` the volume mount root. This database is deliberately disposable; deleting/replacing its Pod loses the local test database. Do not use it for production or durable development data.
- Waits for PostgreSQL startup and a real authenticated `SELECT 1` through PgBouncer, then verifies that the Service has a ready endpoint.
- Generates the database name/user/password automatically, stores them in `flowlesshub-local-database-credentials`, and reuses that Secret on reruns. After database readiness, derives and creates all three runtime URLs in `flowlesshub-runtime-secrets` automatically. No manual credential entry, credential file, Secret manifest, or credential value is added to Git.

The three runtime keys use in-cluster Service DNS:

| Key | Endpoint |
|---|---|
| `DATABASE_URL_API` | `flowlesshub-local-database:6432` (PgBouncer, transaction pooling) |
| `DATABASE_URL_WORKER` | `flowlesshub-local-database:5432` (direct PostgreSQL) |
| `DATABASE_URL_MIGRATE` | `flowlesshub-local-database:5432` (direct PostgreSQL) |

The local-only database resources are created dynamically by the helper. They are not part of `deploy/k8s/base` and are not a production database topology. Production/remote clusters must still provide managed PostgreSQL/PgBouncer endpoints and provision the runtime Secret through their selected secret manager.

Once the helper reports `Local FlowlessHub Kubernetes runtime is ready`, execute the migration-first sequence:

```powershell

if ($LASTEXITCODE -ne 0) { throw "Runtime Secret provisioning failed" }

    kubectl describe job flowlesshub-migrate --namespace flowlesshub
    kubectl logs job/flowlesshub-migrate --namespace flowlesshub
    throw "Migration Job did not complete successfully; do not roll out workloads"
}
kubectl logs job/flowlesshub-migrate --namespace flowlesshub

# Workloads roll only after migration completion.
kubectl apply -k .\deploy\k8s\base
if ($LASTEXITCODE -ne 0) { throw "Kubernetes workload apply failed" }
```

## 11. Mandatory artifact-relocation standard for all future bakes

Every FlowlessHub PowerShell runbook must begin with this order:

1. Resolve Git repository root.
2. Move the patch from repository root to `%TEMP%` before any `git status`/clean-tree check.
3. If both patch copies exist, compare SHA-256; remove the repository copy only when identical; otherwise stop.
4. Verify exact HEAD and the baseline blobs of existing files being patched.
5. Require clean tracked, staged and untracked state.
6. Run `git apply --ignore-space-change --check` and then apply.
7. Run `git -c core.whitespace=cr-at-eol diff --check`.

Never place a downloaded patch in the repository and run clean-tree validation before relocating it. Keep patch artifacts in `%TEMP%` for the entire execution. This is the mandatory standard for subsequent FlowlessHub bake runbooks.
