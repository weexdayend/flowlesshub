## 1. Safety contract

- Only the FlowlessHub database is read for backup.
- Restore runs in a separate container named `flowlesshub-restore-drill-*`.
- The restore container has `--network none`, no published ports, a 256 MiB memory limit, swap disabled, and a 0.50 CPU limit.
- The backup directory is mounted read-only in the restore container.
- The restore container uses an anonymous ephemeral PostgreSQL data volume and `docker run --rm`; it is removed when stopped.
- A dedicated `.vps-runtime/backup.lock` serializes backup and restore-drill scripts.
- The scripts never invoke `docker compose down`, `docker rm` on production services, volume prune, system prune, or any Petshop command.
- Do not change or display `.vps-runtime/.env`; it must remain Git-ignored with mode `600`.
- Do not run production migrations while a backup is running. Take and verify the backup before a migration window.
- Do not run two backup/restore drills concurrently.
- If a stale container carrying `com.flowlesshub.scope=restore-drill` exists, the restore script stops and asks for inspection. It does not automatically remove a stale resource.

## 3. Artifact layout

For an archive named `flowlesshub-YYYYMMDDTHHMMSSZ.dump`, the backup creates:

- `.dump` — PostgreSQL custom-format archive.
- `.dump.sha256` — SHA-256 sidecar.
- `.dump.manifest` — non-secret source and database metadata.

All three artifacts have mode `600`, in a directory with mode `700`.

The manifest records UTC timestamp, source repository commit, active color, database name, PostgreSQL server version, source database size, user-schema count, user-relation count, artifact filename, and SHA-256. It does not contain database credentials.

## 4. Script behavior

The repository root .gitattributes enforces `*.sh text eol=lf`. Keep all Bash scripts in LF format on Windows and Linux.

### `scripts/vps/backup-db.sh`

- Validates runtime `.env` mode/ignore status, local PostgreSQL validation image, PostgreSQL health, active-color state, Git commit, and free disk.
- Takes a logical `pg_dump --format=custom --no-owner --no-privileges` through the FlowlessHub Compose PostgreSQL service.
- Writes to a private temporary file and removes partial/final artifacts on any failure before the complete marker is set.
- Checks the archive catalog with `pg_restore --list` in a network-isolated helper container limited to 128 MiB RAM and 0.25 CPU, with swap disabled.
- Publishes the archive, checksum, and manifest and invokes `verify-backup.sh` before reporting success.

### `scripts/vps/verify-backup.sh`

- Accepts exactly one direct archive file under `.vps-runtime/backups`.
- Requires the archive, `.sha256`, and `.manifest` sidecars with mode `600`.
- Checks manifest identity/metadata, SHA-256, PostgreSQL major version, and archive catalog readability.
- Refuses an implicit Docker image pull.

### `scripts/vps/restore-drill.sh`

- Requires one verified archive and obtains the backup/restore lock.
- Checks RAM, swap, disk, local PostgreSQL image, absence of another restore-drill container, production PostgreSQL health, and active-color state.
- Creates one isolated temporary PostgreSQL container with no network, no host ports, 256 MiB memory, no swap, 0.50 CPU, and an ephemeral anonymous data volume.
- Restores with `pg_restore --exit-on-error --single-transaction --no-owner --no-privileges`.
- Compares restored user-schema and user-relation counts to the backup manifest and verifies the `platform` schema exists.
- Rechecks production PostgreSQL health and active-color state.
- Stops the exact labelled temporary container on exit. `--rm` removes the container and its anonymous data volume. If interrupted with `SIGKILL` or host failure, inspect the exact labelled resource before any manual cleanup.
