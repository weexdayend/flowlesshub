## 5. Manual acceptance scenarios

- Bootstrap the first owner successfully; inspect only non-secret identity/organization/membership counts.
- Repeat bootstrap and confirm refusal without changes.
- Concurrently attempt two initial bootstraps; exactly one transaction may succeed.
- Login with correct credentials and verify a host-only HttpOnly Secure SameSite=Lax session cookie; response JSON must not contain the token.
- Login with wrong email/password and confirm identical generic status/body; verify no credential values in app logs.
- `/v1/auth/me` returns the authenticated user and only active organization memberships.
- Logout revokes the exact session; replaying the previous cookie fails.
- Expired, revoked, disabled-user, suspended-membership, and suspended-organization cases fail closed.
- Cross-origin POST and untrusted Origin are rejected; allowed web Origin receives exact credentialed CORS headers, never `*`.
- Change the selected organization ID to a tenant where the user is not a member; access is denied with no data leakage.
- S1.1 exposes no membership mutation endpoint. Do not simulate owner removal/demotion in this slice; final-active-owner protection and concurrent ownership-transfer tests are mandatory before S1.2 exposes membership mutations.
