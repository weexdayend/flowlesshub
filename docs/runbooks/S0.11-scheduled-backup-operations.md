## 1. Safety and stop conditions

- Preserve Blue/Green state. Do not restart, recreate, or switch FlowlessHub application services for this backup checkpoint.
- Do not modify Petshop containers, databases, volumes, networks, ports, Compose files, or Nginx virtual hosts. Do not touch Frictiona.
- Never run global Docker prune or `docker compose down`/`down -v`.
- Never restore into production. The S0.10 restore was isolated and already accepted; do not repeat it here.
- Keep backup, verifier, restore, off-site upload, and retention operations serialized through `.vps-runtime/backup.lock`.
- Keep `.vps-runtime/.env`, `.vps-runtime/offsite.env`, `.vps-runtime/backup-retention.env`, and the Restic password file private and outside Git. Mode 0600; runtime directories mode 0700. Both off-site upload and retention resolve `RESTIC_PASSWORD_FILE` with `realpath -e` and reject any canonical path outside the canonical `.vps-runtime` directory; a textual prefix check is not sufficient.
- Never print, paste, or log credentials, environment values, Restic passwords, SSH keys, or database passwords.
- Preserve memory/swap/disk guards. Stop on guard failure; do not lower a threshold.
- Do not install/enable the timer, run `restic init`, enable deletion, or set auto-prune without explicit owner decisions.
- No RPO/RTO is claimed. A snapshot-list check is not proof of restore capability. Off-site upload must read back the archive triplet and compare SHA-256 before creating a marker; this still does not replace a PostgreSQL restore drill or full repository integrity audit.

**Mode:** Read-only to backup archive groups
**Purpose:** Validate candidate classification without deleting files.


A dry-run candidate requires an intact local archive triplet, matching checksum/manifest, a versioned marker containing each artifact's read-back SHA-256, and the exact Restic snapshot ID still present in the remote repository. This fresh targeted artifact read-back is not a PostgreSQL restore drill or a full repository integrity audit. The script does not run `restic forget` or `restic prune`.

Local deletion requires all of: owner-approved keep count, `FLOWLESSHUB_BACKUP_RETENTION_ENABLED=1`, `FLOWLESSHUB_BACKUP_RETENTION_ALLOW_DELETE=1`, remote snapshot credentials/config, and explicit manual `--apply`. ## 8. Phase F — install production systemd unit/timer (activation separately gated)

Before install, confirm the service user `ubuntu` exists and has permission to access `/var/run/docker.sock` (usually via the `docker` group). The service file includes `SupplementaryGroups=docker`; do not broaden permissions beyond what is required. Because `ProtectHome=true` hides `/home/ubuntu`, the unit explicitly sets `RESTIC_CACHE_DIR=/tmp/flowlesshub-restic-cache`; `PrivateTmp=true` keeps this cache private to the service.

**[VPS — UBUNTU BASH]**
**Directory:** `/opt/flowlesshub`
**Mode:** Mutating systemd unit files only; timer remains disabled
**Purpose:** Install and parse the service/timer without activating scheduled jobs.

```bash
set -Eeuo pipefail
cd /opt/flowlesshub
id ubuntu
test -S /var/run/docker.sock
getent group docker
sudo install -m 0644 deploy/systemd/flowlesshub-backup.service /etc/systemd/system/flowlesshub-backup.service
sudo install -m 0644 deploy/systemd/flowlesshub-backup.timer /etc/systemd/system/flowlesshub-backup.timer
sudo systemd-analyze verify /etc/systemd/system/flowlesshub-backup.service /etc/systemd/system/flowlesshub-backup.timer
sudo systemctl daemon-reload
sudo systemctl is-enabled flowlesshub-backup.timer || true
sudo systemctl is-active flowlesshub-backup.timer || true
```

Do **not** run `systemctl enable --now` here. Confirm it remains disabled/inactive. `Persistent=true` means enabling after a missed timer event can cause a catch-up execution; consider local resource headroom and current lock state before activation.
