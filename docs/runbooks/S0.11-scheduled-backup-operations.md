## 1. Safety and stop conditions

- Preserve Blue/Green state. Do not restart, recreate, or switch FlowlessHub application services for this backup checkpoint.
- Do not modify Petshop containers, databases, volumes, networks, ports, Compose files, or Nginx virtual hosts. Do not touch Frictiona.
- Never run global Docker prune or `docker compose down`/`down -v`.
- Never restore into production. The S0.10 restore was isolated and already accepted; do not repeat it here.
- Keep backup, verifier, restore, off-site upload, and retention operations serialized through `.vps-runtime/backup.lock`.
- Keep `.vps-runtime/.env`, `.vps-runtime/offsite.env`, `.vps-runtime/backup-retention.env`, and the Restic password file private and outside Git. Mode 0600; runtime directories mode 0700. Both off-site upload and retention resolve `RESTIC_PASSWORD_FILE` with `realpath -e` and reject any canonical path outside the canonical `.vps-runtime` directory; a textual prefix check is not sufficient.
- Never print, paste, or log credentials, environment values, Restic passwords, SSH keys, or database passwords.
- Preserve memory/swap/disk guards. Stop on guard failure; do not lower a threshold.
- Do not install/enable the timer, run `restic init`, enable deletion, or set auto-prune without explicit owner decisions.
- No RPO/RTO is claimed. A snapshot-list check is not proof of restore capability. Off-site upload must read back the archive triplet and compare SHA-256 before creating a marker; this still does not replace a PostgreSQL restore drill or full repository integrity audit.

## 5. Phase C — policy decisions (owner must approve first)

Do not substitute guessed values. Record decisions in `CHECKPOINTS.md` and the acceptance record before activation:

1. **Cadence:** package proposes daily `03:00 UTC` with up to 15 minutes random delay (`10:00 WIB`). Approve or change explicitly.
2. **Off-site provider:** select a private S3-compatible service, endpoint, bucket, and region. None is selected in this package.
3. **Credentials:** issue least-privilege bucket credentials. Put them only in protected `.vps-runtime/offsite.env`; never paste values into chat.
4. **Restic password:** provision a high-entropy password file under `.vps-runtime/`, mode 0600, and store a secure recovery copy outside the VPS. Both scripts canonicalize its path and refuse `..`/symlink resolution that escapes `.vps-runtime`. Losing it means losing the ability to decrypt the repository.
5. **Retention:** select `KEEP_LAST` (at least 2). Confirm local disk needs and cost. Remote retention/pruning requires a separate policy.
6. **Deletion:** explicitly approve local backup deletion. The default remains disabled and dry-run.
7. **Alerts:** select a destination or accept journald-only monitoring for the first phase.
8. **Restore cadence and RPO/RTO:** set only after capacity review and owner approval. No objectives are implied by this code.

## 6. Phase D — provision off-site repository (optional; only after provider approval)

The template uses Restic with an S3-compatible HTTPS endpoint. This package does not select a provider, create a bucket, provision keys, or initialize a repository.

**[VPS — UBUNTU BASH]**
**Directory:** `/opt/flowlesshub`
**Mode:** Mutating protected runtime configuration; remote repository initialization
**Purpose:** This optional phase may run only after provider, bucket, credentials, password recovery, and data residency/cost/access controls have been approved.

1. Install a trusted, pinned Restic release through the VPS's approved package mechanism. Do not use an unpinned `curl | sh` installer.
2. Copy `deploy/vps/offsite.env.example` to `.vps-runtime/offsite.env`, edit it in a protected editor without printing it, fill provider values, then `chmod 600 .vps-runtime/offsite.env`.
3. Create a separate password file at the approved path inside `.vps-runtime`; set mode 600 and owner to the service execution account. Never put the password directly in the env file or process arguments.
4. Keep `FLOWLESSHUB_OFFSITE_ENABLED=0` until the repository initialization and a manual test are reviewed.
5. Validate `RESTIC_REPOSITORY` format `s3:https://<endpoint>/<bucket>/<prefix>`, access-key scope, region, endpoint TLS, and repository encryption recovery.
6. Initialize exactly once as a deliberate owner action using the protected config. The automation script deliberately does not execute `restic init`.
7. Verify the existing repository can be listed before setting `FLOWLESSHUB_OFFSITE_ENABLED=1`.

No provider initialization command is included here because endpoint and credential values are unresolved. Do not invent them.

## 7. Phase E — retention policy provisioning (optional; owner approval only)

**[VPS — UBUNTU BASH]**
**Directory:** `/opt/flowlesshub`
**Mode:** Mutating protected runtime config only; no backup deletion in this phase
**Purpose:** Configure the approved local keep count while retaining disabled deletion defaults.

Copy `deploy/vps/backup-retention.env.example` to `.vps-runtime/backup-retention.env`; edit it without printing values; set mode 600 and owner to the service execution account. Keep these defaults until an explicit approval exists:

```text
FLOWLESSHUB_BACKUP_RETENTION_ENABLED=0
FLOWLESSHUB_BACKUP_RETENTION_ALLOW_DELETE=0
FLOWLESSHUB_BACKUP_RETENTION_AUTO_PRUNE=0
```

When approved, set `FLOWLESSHUB_BACKUP_RETENTION_ENABLED=1` and a `FLOWLESSHUB_BACKUP_RETENTION_KEEP_LAST` integer of at least 2. Keep `ALLOW_DELETE=0` and `AUTO_PRUNE=0` for the first dry-run cycle.

Run a dry-run only after the config has been reviewed:

**[VPS — UBUNTU BASH]**
**Directory:** `/opt/flowlesshub`
**Mode:** Read-only to backup archive groups
**Purpose:** Validate candidate classification without deleting files.

```bash
cd /opt/flowlesshub
./scripts/vps/backup-retention.sh --dry-run
```

A dry-run candidate requires an intact local archive triplet, matching checksum/manifest, a versioned marker containing each artifact's read-back SHA-256, and the exact Restic snapshot ID still present in the remote repository. During `--apply`, retention additionally uses `restic dump` to read all three files back from that exact snapshot again and compares them with the local files immediately before deletion. This fresh targeted artifact read-back is not a PostgreSQL restore drill or a full repository integrity audit. The script does not run `restic forget` or `restic prune`.

Local deletion requires all of: owner-approved keep count, `FLOWLESSHUB_BACKUP_RETENTION_ENABLED=1`, `FLOWLESSHUB_BACKUP_RETENTION_ALLOW_DELETE=1`, remote snapshot credentials/config, and explicit manual `--apply`. Do not set `AUTO_PRUNE=1` until several scheduled dry-run cycles have been inspected and owner approval is recorded.

## 8. Phase F — install systemd unit/timer (optional; owner approval only)

Before install, confirm the service user `ubuntu` exists and has permission to access `/var/run/docker.sock` (usually via the `docker` group). The service file includes `SupplementaryGroups=docker`; do not broaden permissions beyond what is required. Because `ProtectHome=true` hides `/home/ubuntu`, the unit explicitly sets `RESTIC_CACHE_DIR=/tmp/flowlesshub-restic-cache`; `PrivateTmp=true` keeps this cache private to the service.

**[VPS — UBUNTU BASH]**
**Directory:** `/opt/flowlesshub`
**Mode:** Mutating systemd unit files only; timer remains disabled
**Purpose:** Install and parse the service/timer without activating scheduled jobs.

```bash
set -Eeuo pipefail
cd /opt/flowlesshub
id ubuntu
test -S /var/run/docker.sock
getent group docker
sudo install -m 0644 deploy/systemd/flowlesshub-backup.service /etc/systemd/system/flowlesshub-backup.service
sudo install -m 0644 deploy/systemd/flowlesshub-backup.timer /etc/systemd/system/flowlesshub-backup.timer
sudo systemd-analyze verify /etc/systemd/system/flowlesshub-backup.service /etc/systemd/system/flowlesshub-backup.timer
sudo systemctl daemon-reload
sudo systemctl is-enabled flowlesshub-backup.timer || true
sudo systemctl is-active flowlesshub-backup.timer || true
```

Do **not** run `systemctl enable --now` here. Confirm it remains disabled/inactive. `Persistent=true` means enabling after a missed timer event can cause a catch-up execution; consider local resource headroom and current lock state before activation.

## 9. Phase G — one-shot manual test before timer activation

Only after exact-SHA CI passes, the VPS source checkout is on the accepted detached SHA, provider policy is approved (or explicitly accepted as local-only), protected files are configured, and a quiet resource window is confirmed.

**[VPS — UBUNTU BASH]**
**Directory:** `/opt/flowlesshub`
**Mode:** Mutating FlowlessHub backup artifact creation; optional network upload; retention dry-run by default
**Purpose:** Run one manual one-shot service and inspect outcome before timer enablement.

```bash
set -Eeuo pipefail
cd /opt/flowlesshub
sudo systemctl start flowlesshub-backup.service
sudo systemctl show flowlesshub-backup.service -p Result -p ExecMainStatus -p ActiveEnterTimestamp -p InactiveEnterTimestamp
sudo journalctl -u flowlesshub-backup.service --since '2 hours ago' --no-pager
```

Expected success: service `Result=success`, exit status 0, backup archive triplet present with required permissions and checksum, and no application service restart. If off-site is configured/enabled, confirm a matching Restic snapshot ID, successful remote `dump` read-back SHA-256 comparisons for the archive triplet, and a matching versioned `.offsite-uploaded` marker. If off-site is disabled, the local archive must remain and the log must say no off-site upload was attempted. Retention must report dry-run until deletion is explicitly approved.

Stop on failed health/resource guards, backup errors, upload errors, incomplete sidecars, checksum mismatch, missing Restic snapshot, or unexpected Docker resources. Do not respond with a blind retry or Docker cleanup.
